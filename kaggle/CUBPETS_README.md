# CUB-200 / Oxford-Pets view-rules table on Kaggle (ResNet32x4 teacher, 16 notebooks)

The table has 48 runs: 2 datasets (CUB-200, Pets) × 2 pairs (ResNet32x4 → ResNet8x4, ResNet32x4 → ShuffleNetV2) ×
4 arms (prop, frn, low, kd) × 3 seeds. The runs are spread over **16 notebooks**, `kaggle/cubpets_01.ipynb` …
`cubpets_16.ipynb`, so that 8 accounts × 2 concurrent sessions run all of them at once. Each notebook runs one job
per T4. The code is `cubpets/` (see `cubpets/README.md`). The split is in `cubpets/plan.py`. The notebooks are
generated by `kaggle/make_cubpets_notebooks.py` and pinned to the git tag `cubpets-v4`.

Nothing has to be uploaded or attached. Each notebook does the following:
1. downloads CUB / Pets from Hugging Face and rebuilds the 96-px tensors, checking them against the paper's tensors
   (sha256 of the tensor contents);
2. downloads the ResNet32x4 teacher from the GitHub release
   [`cubpets-teachers-v2`](https://github.com/Soobiwan/epkd-vision/releases/tag/cubpets-teachers-v2). If a teacher is not
   published yet, the notebook polls for it every 2 min and the GPU runs another job from its queue meanwhile (for
   example Pets KD while the CUB teacher is still training).

## v4 (11-26 evening): strong teachers — start every notebook fresh, do NOT attach earlier output

Tag `cubpets-v4` changes only the teachers. The ResNet32x4 teachers trained from scratch at 96 px were weak (CUB 62.86,
Pets 75.31: several students beat them). The v4 teachers (release `cubpets-teachers-v2`) are the same ResNet32x4
architecture at the same 96 px, initialised from the CIFAR-100 ResNet32x4 and trained long (`cubpets/train_teacher.py`);
their accuracy and recipe are in the release's `tea_<ds>_r32x4.json`. Students, arms, seeds and the split over the 16
notebooks are unchanged. v4 run folders carry version v4; `collect_cubpets.py` counts only v4 results
(`--any-version` for the v3 tables). To start: import the notebook again from `main` (= tag `cubpets-v4`), GPU T4 x2,
Internet on, Save & Run All. A notebook started before the teachers are published waits for them (polls every 2 min).

The Pets teacher is published first, the CUB teacher about 2-3 h later. Start notebooks **06-08 and 10-16** (they hold
all Pets runs and run them while the CUB teacher is still missing) as soon as `tea_pets_r32x4.json` is on the release,
and **01-05 and 09** (CUB only) once `tea_cub_r32x4.json` is there; started earlier they would only wait and use quota.

## v3 (11-25 evening): start every notebook fresh — do NOT attach earlier output

Tag `cubpets-v3` changes two things against `cubpets-v1` / `cubpets-v2` (author's decisions):
* The random-window arm is now **`frn`**: grid-free random windows, uniform over all valid pixel offsets, drawn once
  per image and stage and fixed for the stage (`--view-set frn1,frn2,frn3`, as in the epkd2 runs `frc_anc` /
  `{cub,pets}_frn_anc`). It replaces `rfix` (`rnd1,rnd2,rnd3`, windows on the stride-24 grid). Run names are
  `<ds>_<pair>_frn_s<k>`.
* The teachers on the release `cubpets-teachers` are now the **best-test-epoch** checkpoints: Pets 75.31 %
  (sha256 `40f8b7c6…`), CUB 62.86 % (sha256 `8e640d2c…`). Before, they were the final-epoch checkpoints (Pets 75.06,
  CUB 62.65).

Every earlier session used the `rnd` windows, the final-epoch teachers, or both. Its runs are **not** part of this
table. To start a v3 run:
1. Import the v3 notebook again (from `main`, which equals the tag `cubpets-v3`), or edit the old notebook so that
   `REF` is `cubpets-v3`.
2. Remove any **Add Input** that points at an earlier version's output.
3. Run **Save & Run All**.

Safety net: v3 run folders carry `cubpets_run.json` (version v3 and the teacher sha256). The runner restores only
v3 folders, and it sets aside a folder whose teacher differs from the current one. `collect_cubpets.py` counts only
v3 results (`--any-version` to include the old runs). So an earlier output attached by mistake is ignored. Still, do
not attach one.

The v1/v2 notebooks that contained `rfix` runs: `cubpets_01` (cub_sv2_rfix_s0); `cubpets_03` (cub_sv2_rfix_s1); `cubpets_04` (cub_sv2_rfix_s2); `cubpets_06` (cub_r8x4_rfix_s0); `cubpets_07` (cub_r8x4_rfix_s1); `cubpets_09` (cub_r8x4_rfix_s2); `cubpets_10` (pets_sv2_rfix_s0); `cubpets_12` (pets_sv2_rfix_s1); `cubpets_13` (pets_sv2_rfix_s2); `cubpets_15` (pets_r8x4_rfix_s0, pets_r8x4_rfix_s1); `cubpets_16` (pets_r8x4_rfix_s2). The mapping notebook → account and the queues are otherwise
unchanged, and so are the estimated hours (`frn` costs the same as `rnd`).

The run list of each notebook is in the table at its top. The hours are estimates for one job per T4, uncertain by
about ±30 %. Per-step times come from a micro-benchmark on an RTX 2080 Ti: teacher forward plus student
forward/backward, at 96 px and at the view sizes. They agree with the CUB teacher's measured 24.8 s/epoch alone. The
estimate multiplies them by the schedule's step counts, adds evaluation, and takes a T4 as ~2.1× slower than a
dedicated 2080 Ti. A notebook whose CUB jobs wait for the CUB teacher takes that much longer.

The notebook prints the measured s/epoch every 10 min. For CUB ShuffleV2 EP-KD the estimate corresponds to ~180
s/epoch in stage 1 (epochs 1–48, 3 passes) and ~65 s/epoch in the KD stage (epochs 193–240). Above ~220 s/epoch in
stage 1, the run will not finish within one session. It then stops cleanly at 11.5 h and resumes in a second
session (see below). Alternatively, continue it on a local GPU (last section).

**Kaggle quota:** 30 GPU-hours per account per week. One account's two sessions take ~14–18 h, so there is room for
one resume session per account, but not for many.

## Steps for each notebook (author, ~2 min per notebook)

1. kaggle.com → **Create → New Notebook → File → Import Notebook** → upload `kaggle/cubpets_NN.ipynb` (from GitHub:
   *Import* also takes the URL `https://github.com/Soobiwan/epkd-vision/blob/main/kaggle/cubpets_NN.ipynb`).
2. Right panel → **Session options**: Accelerator **GPU T4 x2**; **Internet on** (phone-verified account needed);
   Persistence: none needed.
3. **Save Version** (top right) → **Save & Run All (Commit)** → Save. The run continues after you close the tab.
   Progress: **View Active Events** or the version's **Logs**.

No dataset needs to be attached. The rebuild installs Pillow 13.0.0, which needs Python ≥ 3.11; Pillow 11.3 and 12.0
give different pixels. If the data check ever fails (the log says `the rebuilt tensors differ`), use the fallback
below.

## A session died or hit the 12-h limit

Each run saves `latest.pt` after every epoch. On reaching 11.5 h, the script stops each job right after its next
epoch checkpoint, so the version ends cleanly and its output is saved. To continue:

1. Open the notebook (**Edit**) → **Add Input → Your Work → Notebooks** → select the same notebook. This attaches the
   output of its latest version, which has `cubpets/runs/...` and `cubpets_nbNN.zip`.
2. **Save Version → Save & Run All** again. Finished runs are skipped, and unfinished runs resume from their last
   epoch.

Only v3 output can be resumed this way (see above). If a version failed without output (crash before saving), the runs start over. Its log shows the error: `stdout tail`
of the run.

## Results

When a version finishes, its **Output** tab has `cubpets_nbNN.zip`, which holds all run folders plus `results/` and
`summary.json`. Download it, either from the Output tab (**Download**) or with
`kaggle kernels output <user>/<notebook-slug> -p downloads/<NN>`. Then:

    python kaggle/collect_cubpets.py downloads/        # tables: arm x (dataset, pair), mean ± sd, Δ vs prop
    python kaggle/collect_cubpets.py downloads/ --csv cubpets_table.csv

`collect_cubpets.py` reads the zips or extracted folders, any number of them. It lists missing runs. A run present in
several downloads is counted once, using the copy with the most epochs. The metric is the best test accuracy
(`--metric final` for the last epoch).

The marker files `cubpets/DONE` / `cubpets/INCOMPLETE` in the output tell whether every run of the notebook finished.

## Fallback: Kaggle dataset with the prepared tensors (only if the data check fails)

`~/ASI/ep-kd-paper/kaggle_upload/epkd-cubpets/` has `cub_uint8.pt`, `pets_uint8.pt`, the two teacher checkpoints and
`dataset-metadata.json`. To use it:
1. kaggle.com → **Datasets → New Dataset** → drag in the 4 files, title `epkd-cubpets`, private → **Create**. Or, from
   the folder, set your user name in `dataset-metadata.json` (`id`) and run `kaggle datasets create -p .`.
2. Dataset page → **Share** → add the other 7 accounts (viewer).
3. In each notebook: **Add Input → Datasets → epkd-cubpets**, then Save & Run All. The script finds `<ds>_uint8.pt`
   under `/kaggle/input` and uses it if its hashes match.

## Running some of the runs locally instead

    python cubpets/get_data.py --out data cub pets
    python cubpets/kaggle_run.py --runs cub_sv2_prop_s0,cub_sv2_frn_s0 --out runs_local --work work_local

With 2 GPUs, the first listed run goes to GPU 0, the second to GPU 1, and so on. To use a local teacher instead of
the release, pass `--teacher-dir <dir with tea_<ds>_r32x4.pth>`. To continue a Kaggle run locally, put its run folder
under `runs_local/runs/` (or pass `--restore-from downloads/`).
