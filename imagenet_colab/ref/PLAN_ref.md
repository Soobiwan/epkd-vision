## 2b. Edge-aligned candidate windows (`tgsc.edge_align_windows`, ON in all four recipes)
Ported from the CIFAR code (`cvpr_epkd/code/src/tgsc_kd/tgsc.py`).  The plain grid
`range(0, size-crop+1, stride)` stops short of the image edge: with analysis short side 256, 112px windows
at stride 56 start at 0/56/112 and never cover rows 224-255; the 224px tail stage (stride 56) had ONE
window on square images (3 on 4:3), so `k_per_img` 10/8 and top-3+low-2 were mostly not reachable.
Flag on: a final window flush with the edge is appended per axis (`tgsc.window_starts`);
`_build_windows_by_pool(..., edge_align)` pools densely (stride 1) and index_selects the start offsets
(values at shared grid positions are bit-identical to the strided pool); `_boxes_from_grid(..., edge_align)`
maps grid indices through the same start list.  Threaded through `ImageNetTGSCPreprocessor.emit_stage_rows`
(the only ImageNet precompute / verify path), `build_bestcrop_dataset_batchwise` / `TGSCPreprocessor`
(CIFAR-style path) and `visualization.analyze_imagenet_tgsc_sample`.  Flag off (default) = old code
bit-for-bit (same windows, rows and cache keys; checked against commit 2bdb699 on real images).
The cache-key payload gets `tgsc.edge_align_windows: true` only when on.

Windows per stage before -> after (A and B recipes are identical here; short side 256):
| crop | stride | starts on side 256 | 256x256 | 256x341 | 256x384 |
|---|---|---|---|---|---|
| 112 (A1/B1) | 56 | 0,56,112 -> +144 | 9 -> 16 | 15 -> 24 | 15 -> 24 |
| 140 (A1/B1) | 50 | 0,50,100 -> +116 | 9 -> 16 | 15 -> 24 | 15 -> 24 |
| 168 (A1/B1) | 46 | 0,46 -> +88 | 4 -> 9 | 8 -> 15 | 10 -> 18 |
| 196 (A1/B1) | 42 | 0,42 -> +60 | 4 -> 9 | 8 -> 15 | 10 -> 18 |
| 224 (A2/B2) | 56 | 0 -> +32 | 1 -> 4 | 3 -> 8 | 3 -> 8 |
Precompute cost: ~25 % slower per image (dense pooling + more candidates actually scored at 224).

## 4. DDP equivalence (src/tgsc_kd/ddp_trainer.py)
16 micro-batches of 32 rows per 512-row step are spread over 3 ranks (6/5/5, rotating); loss scaled by
rows/512*world so DDP's average equals the original accumulated gradient exactly; BN still sees 32-row
batches; BN running stats averaged over ranks before eval/checkpoint (broadcast_buffers off).
Parquet files are split over ranks per epoch (seeded shuffle, row-balanced), then over workers; per-worker
shuffle buffer kept at the original 512 rows.  An epoch ends for all ranks when one rank runs out
(logged `dropped_rows_end_of_epoch`, typically a few hundred of ~6.4 M rows).  Validation sharded over ranks,
fp32, sums all-reduced.  Same checkpoint format (+ AMP scaler); auto-resume from `latest.pt`.

## Speed results (rows/s = training crops/s; one image yields ~5 rows)
Power limit was raised to 250 W on all GPUs (by the author) before these measurements.  ALL numbers
below were taken while the CIFAR queue kept 2 jobs at ~100 % on every GPU and the CPU at load ~15/20, so
they are lower bounds and only the ratios are meaningful.  The launcher runs a clean benchmark (original
loop vs tuned 3-GPU DDP) just before A1 starts: `logs/clean_bench.log`.

Single GPU (GPU1), A1 RN50->MNv1, 112 px, synthetic index (`bench/index`, throughput only), steady state:
| config | rows/s | vs original |
|---|---|---|
| original KDTrainer loop, 2 workers, no pin (`bench_orig.py`) | 280 | 1.00 |
| DDP loop (no per-micro-batch .item()/mask syncs), same loader | ~335 | 1.20 |
| + 6 workers/rank, pin_memory, prefetch 4 | ~430 | 1.54 |
| + channels_last (fp32) | ~400 | ~1.4 (noise; no gain in fp32) |
| + teacher fp16 under inference_mode | ~490 | 1.75 |
| + AMP fp16 student (GradScaler) **[kept]** | ~740 | 2.64 |
| AMP without channels_last | ~715 | 2.55 |
B2 RN34->RN18 at 224 px: fp32 197 -> AMP+fp16 teacher 536 rows/s (2.7x).

3-GPU DDP (all GPUs shared with CIFAR jobs), 6 workers/rank, pin, prefetch 4, channels_last:
A1 112 px fp32 ~800, AMP ~1170 rows/s (= 4.2x the original single-GPU loop under the same contention);
A2 224 px fp32 ~270; B2 224 px fp32 ~330 rows/s.
Not kept / not needed: NCCL P2P knobs (`nvidia-smi topo -p2p`: CNS, chipset does not support P2P, NCCL
uses SHM automatically); `static_graph` (internal assert together with `no_sync` in torch 2.6, off);
GPU JPEG decode (would change pixels vs PIL; CPU decode is not the bottleneck with 18 workers);
`gradient_as_bucket_view` on; bucket_cap_mb 25 (default; models are 4-12 M params).

AMP decision (numerics): kept, because short-run loss curves match fp32 within noise
(`bench/amp_compare_a1.json`, `bench/amp_compare_b2.json`; same init + same data order, fp32 with another
seed as the noise reference):
* A1 112 px, 200 steps: mean |AMP - fp32| per-step loss 0.009 vs seed noise 0.043 (20-step smoothed 0.0046
  vs 0.018); last-50-step mean loss 5.5368 vs 5.5365.
* B2 224 px, 100 steps: 0.020 vs seed noise 0.058 (smoothed 0.0098 vs 0.0102).
To train in fp32 instead, write the flags to `train_args.txt` (read at every (re)launch), e.g.
`--num-workers 6 --val-workers 5 --pin-memory 1 --prefetch-factor 4 --channels-last 1 --teacher-fp16 0 --amp 0 --progress-every 500`.

Precompute (per-image path is latency bound: many tiny kernels + host syncs): contended GPU, RN50 fused
A1+A2: cudnn.benchmark ON (original) 0.9 img/s (autotunes every new image shape) -> OFF 5.7 img/s; 3
processes on one GPU 8.5 img/s total.  Launcher uses 3 processes x 2 decode workers per GPU.

## Time estimates (clean machine; extrapolated from the original single-GPU epoch times and the measured
ratios, so +-30 %; the logs record real per-epoch times)
Original: RN50->MNv1 epochs 2.0 h (112) .. 4.3 h (196) for ~5.1 M rows; tail 3.5 h/epoch.  New phase-1
epochs have ~6.4 M rows (top-3 + low-2).  With ~4x throughput:
* caches: RN50 ~4-6 h, RN34 ~3-4 h (9 processes on 3 GPUs; partly overlappable with the end of the CIFAR queue).
* A: A1 80 epochs ~0.9 h/epoch avg (~0.5 h at 112 -> ~1.2 h at 196) ~ 70-75 h; A2 20 x ~0.8 h ~ 16 h -> ~3.7 days.
* B: similar, ~3.5 days (RN34 cache built after A unless the early window allowed it).
* Total after the CIFAR queue ends: ~7.5-8 days (fp32 would be ~11-12 days).

## Full-image anchor (EP-KD full-input objective) — added 2026-11-03, default OFF
Port of the CIFAR E3 candidate (cvpr_epkd/results/AUDIT_TGSC_IMPROVEMENTS.md). `tgsc.full_anchor` (weight, 0 = off)
and `tgsc.full_anchor_frac` (fraction of distinct source images per micro-batch) in TGSCConfig; not in the cache key.
At restricted stages (resolution < eval_crop_size) each distinct source image of a micro-batch also gets one random
224x224 window (+ flip) of its 256-short-side image, and the loss adds full_anchor * KD(student, teacher) on it.
Restricted and anchor views go through ONE DDP forward (`_AnchorPair`): a second forward through `.module`
fails in the reducer. Backups: backup_pre_anchor/. Tests: tests/test_full_anchor.py (exact windows, frac);
tests/manual_ddp_anchor_pair_check.py (2-rank gloo, no_sync + paired forward: gradients identical to reference).
pytest tests/ -> 189 passed, 8 skipped. Not yet benchmarked on GPU (needs the stage cache): the cost estimate is
+30 % (196 px) to +400 % (112 px) student compute per step at frac 1.0, plus a 224 px teacher forward.
